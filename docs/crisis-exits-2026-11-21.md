# 危机合约 V2：失败/退出回执和额外计数依据

在[任务事务组件](crisis-objectives-2026-11-21.md)之后增加独立、版本化的失败/退出回执。当前仍未开放原生战斗路由，不把此分支当作完整危机合约交付。通关候选明确返回未实现并保留待结算会话；下一继续通关纪录、全部评论、领取和原生闭环。

## 结果与耐久回执

复核既有 REA M81283 的正常 rank 产生路径，及匹配冻结元数据的 FAIL/PASS/COMPLETE 声明，原始依据见[共用 rank 研究](campaign-training-complete-2026-10-21.md#rea正常rank路径与限制)。它不是危机合约实际网络包或所有 GameMode/Hotfix 的证明。本地接纳规则：interrupt 或 giveUp 优先归类 ABORTED；无标志的 rank1 为 FAILED；无标志的 rank2/3 只列 CLEAR_CANDIDATE，不按普通关卡星数发奖，也不以击杀或 percent 替代结果。

新增 `crisis_v2_exits`。先沿用账号/版本/登录、加密载荷、关卡及可选日志编队绑定，再提取有限业务事实。回执包含独立版本、start_hash、规范结果事实、原业务答复和校验和；请求指纹不包含随机 IV、未采用的 telemetry 或压缩日志。失败写 FINISHED，主动退出写 ABORTED，时间和原回执持久保存。仅这些已接分支释放全账号战斗互斥，不写地图任务、分数、评论、奖励、干员或普通关卡。仍由调用方的单一事务统一提交，异常回滚原记录。

相同业务事实可跨序号、不同 IV、服务重启和最新本地登录读取原回执；改变业务结果返回冲突。新登录仍不能接管旧的 STARTED 会话。终态上下文开放读取后，任务参与组件新增 STARTED 检查，防止已失败战斗后来被写成通关进度。普通结算继续拒绝此模式，不能把危机合约回执当普通奖励缓存。

无新表/DDL；回执 JSON 有独立版本，0039 的 STARTED 保存仍可读。启动/恢复只读预检核对静态绑定、终态、事实指纹、业务答复及回执校验和，损坏时先于可写初始化拒绝。旧源码不理解新增终态时会拒绝，不会自动降回待结算；回滚旧版本应同时使用其匹配的旧备份。

## REA 和计数格式

新的冻结 APK 会话实际分析三个方法，共 **3,048 字节**：M66406 LogExtraBattleInfo 572、M66443 BattleStats 构造器 1,364、M32807 ListDictConverter.WriteJson 1,112。容器 SHA-256 `220478780a1ac735c5de9ab5e5d8642e0d35b0ba6afe34f5b9bdabf851876882`，三个请求非空且成功；先前 M66406 的超时回执保留，没有改写失败历史。

- M66406 正常路径向同一字符串/整数池累加，补齐上批缺失方法；与已核 M66405 overwrite 分支区分。
- WriteJson 的虚表调用由本版本 JsonWriter 的 slot7/8/13 对应 WriteStartObject/WriteEndObject/WritePropertyName，循环对键名和值分别写入。因此该转换器写 JSON **对象**，不能仅凭 ListDict 名称猜成 Key/Value 数组。尚未据此宣称所有调用点都采用此转换器。
- BattleStats 构造器有两个同型字符串/整数池；受保护字段偏移不能统一 XOR 后命名。本批没有把仅据声明顺序推断的字段绑定冒称真实危机合约包证据，也没有把一个池中的数字套给另一池。评论管理器的事件/属性格式及此处对象格式是后续选择性计数的依据，全部评论判定仍未接通。

仅采用已命名原方法正常路径。全局符号、虚调用和异常终端返回性的 Ghidra 限制保留；无活动 Hotfix 读取。公共 status/close 成功、控制器句柄已终结、进程 exit=0、输入保持；本阶段没有启动模拟器、读取 Android/玩家对象或官方认证。

## 实际验证与玩家体验

- **102 个不同当前定向用例最新结果通过**，含 39 个新结果/回执用例和 63 个受影响会话/输入绑定/任务事务用例。覆盖 12 种 rank/标志组合、并发、不同序号/IV、重新登录、原始终态保持、清晰拒绝未接通关、回滚、账号与模式隔离、再开战和九种损坏保存的只读拒绝。
- `exits-v1.xml` 为 38 通过/1 失败：新 QA 调用普通结算时漏传两个必需参数。补齐后 `exits-v2.xml` 为 101 通过/1 失败：同一 QA 误写预期错误码，实际既有保护先返回 NATIVE_CONTEXT_UNAVAILABLE。核对源码后只修测试预期；`exits-v3.xml` 单项复验通过。原输出保留，不为补记录重跑全量。Ruff 的一次未用导入及新增 iterable 参数警告已修正，最新 Ruff/空白检查通过。
- `exits-frozen-v1/` 从冻结 20 表 `14457902…` 的五个 STARTED 会话另建隔离副本；三次真实 Python 进程分别完成首次退出、冷重开/不同 IV 重试及备份的新目录恢复重试，均退出 0。**人工构造加密请求**覆盖自然失败及三种 rank 的退出标志，不是客户端实际发送。
- 82 表全行核对：首次仅 battle_sessions 改变，其余 81 表、子会话/start_hash 和现用/源数据保持；第二、第三进程全行与首次终态相等，原业务答复一致。首季实际已关闭，保存中的历史时钟不作为当前开放证明；没有新游戏游玩或 EXE。

本地证据根 `.cache/crisis-20261119/`：`exit-progress-summary-v1.json`、`exits-v1/2/3.xml`、`exits-frozen-v1/phase1/2/3.json` 与 `backup.json`、`rea-exit-counters-v1/`、`mcp-exit-counters-v1/`。官方数据、原始代码/伪代码、QA 数据库和本地登录材料不上传。

完整目标仍包括所有指定玩法、客户端表现、断网/长时验收及最终发行。接入退出分支不替代通关分支；下一把已核结果与必要计数接入通关纪录、评论及完整结算事务，再成对开放原生战斗路由并做新的代表验收。
