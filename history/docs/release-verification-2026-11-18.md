# Windows 发行清单与独立发布验证

用已回读源码 `9e33b04` 和合成打包输出复现旧构建器的两个问题。程序实际报告 `9.4.2` 时，清单仍写 `0.1.0-development`。版本探测新生成的文件也漏出清单，但构建继续返回程序路径。两项结果保存在 `.cache/release-verification-20261118/reproduction-v1/verification.json`。

构建从项目配置读取版本，在 D 盘的独立构建目录暂存文件。PyInstaller 只显式加入三个管理页面文件，并保留依赖的 `_internal` 目录。构建器检查链接、已知本地文件类型和项目数据范围，核对随包页面文件与源码的指纹。实际程序的 `--version` 要与项目版本一致，探测前后的成员、大小及 SHA-256 也要一致。通过后才将带清单的完整目录移入新发行目录。失败的构建暂存保留，便于检查。现有安装仍由各自的原目录管理。[PyInstaller 打包参数](https://pyinstaller.org/en/stable/usage.html)

源码环境可用 `python -m tools.build_release --verify <解压目录>` 检查发行物。退出 `0` 时返回构建编号、声明版本和核验的文件数，文件缺失、多出或指纹变化时退出 `1`。命令只读取文件，执行时机为解压后、首次启动前。旧清单继续支持文件核验，旧版本字段按原清单显示。清单比较提供一致性检查，发布方身份以可信取得的发行物为依据。

22 项独立自动检查通过，覆盖重复构建、旧安装保护、错误版本、探测期间新增或变更文件、嵌套的本地数据类型和清单核验。历史独立开发包 `20261021T224516.553837Z-e5ec1dde` 的 1,079 个文件通过真实只读检查，清单与 EXE 的前后 SHA-256 一致。旧包的程序行为沿用其历史验收记录。
