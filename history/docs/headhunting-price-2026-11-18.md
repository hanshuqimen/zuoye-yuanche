# 寻访价格与导入校验

检查新手、普通双 UP、中坚双 UP 和定向甄选的计费入口时，发现现代卡池直接从常量表取单抽价格。缺字段时会按 600 处理，导入时也接受零、布尔值、小数及其他不能作为余额扣款单位的值。初次专项检查十项中九项失败，使用合法自定义价格的一项通过。原生验收使用的三个卡池在已冻结的数据中单价均为整数 600。本次发现影响异常或不完整的数据，不足以解释历史上的客户端更新报错。

现在，导入带寻访表的数据时，显式声明的单价须为正整数且在系统单项余额范围内。只含新手池或招募所需的旧数据可继续导入。激活现代卡池规则时必须提供匹配的合成玉单价，验证成功的卡池直接携带此价格。单抽、十连及组合支付使用同一个价源，未改动抽选、保底、名单或收据的计算方式。

109 个相关检查通过，包括新增的十项。实际导入合成单价 480 后，十连组合付款、同一请求重试、另一卡池单抽产生 11 条寻访记录，余额共减少 5,280。缺价的现代规则在创建数据库前被拒绝。其余八种不合法字段在发布新缓存前被拒绝。静态检查通过。测试框架仍报告一条 Starlette 测试客户端依赖弃用提示。

只读核验了 `f44199a7…` 与 `e915675d…` 这两个实际导入版本的常量表和寻访表指纹。其中 `DOUBLE_77_0_5`、`CLASSIC_DOUBLE_77_0_2` 与 `SPECIAL_77_0_4` 在历史验收时钟 1791508841 均开放，在本次核对的主机时刻均已结束。重新读取与 `f44199a7…` 匹配的三池规则，目录摘要和各星级名单数量与原始收据一致。没有将这份名单用于另一数据版本。专用限时券、限定与联动等池种，以及新改动的设备表现仍待验证。

本地证据位于 `.cache/gacha-price-20261118`。修改前后检查分别见 `before.xml` 与 `fixed.xml`，匹配版本与开放区间见 `real-table-facts.json`，已有规则复核见 `matched-three-pools.json`。
