# 启动器端口与失败恢复验收

在已回读的 `acdb001` 上复现两个启动问题。端口检查释放套接字后，另一个本机监听器能在初始化期间取得同一端口，导致真正启动时出错。模拟线程无法创建时，清理抛出 `cannot join thread before it is started`，掩盖原错误，也未关闭数据库或释放存档锁。复现使用新 D 盘目录和临时本机端口。[复现记录](project-ledger/EVIDENCE.md)

启动器现在先绑定两个端口，将原套接字交给监听线程。从预留到开始监听期间持续持有套接字。端口无法绑定时报告服务名及端口号。回收代码只等待实际启动的线程，待工作线程结束再释放数据库和存档锁。初始化期间的数据库异常也会关闭连接池。启动失败时保留原错误，未完成的清理仍可再次停止。[Python asyncio 服务套接字](https://docs.python.org/3.12/library/asyncio-eventloop.html#asyncio.loop.create_server)

任一监听线程意外结束时，命令行报告对应的服务并退出。启动窗口停用管理和备份入口，自动停止另一监听线程和工作任务，清理结束后显示端口和存档锁已释放。这个失败路径保留窗口供查看和关闭。两个服务成功启动后显示运行中。

31 项相关检查通过。独立 Windows 进程在无静态游戏数据、无客户端绑定的新存档上完成两次真实本机 TLS 启动及两次 `/health` 响应。初始化暂停时两个端口均拒绝竞争绑定，错误号为 `10048`。正常停止及受控单监听退出后，两端口均可立即重新绑定，存档锁可重开，所有相关线程结束。普通重启保留写入的测试时钟。监听退出时 `terralocal` 命令分发返回 `2`，明确报告管理服务意外停止。测试未操作 Android 或连接外部地址。

两个独立进程各以隐藏的真实 Tk 启动窗口验证一条失败路径。管理端口已占用时显示端口号，窗口可关闭。游戏监听退出后观察到运行中、释放资源以及释放完成的状态变化，管理和备份按钮正确停用，随后可通过停止按钮关闭窗口。两进程均退出 `0`。范围限于控件文字、可用性和关闭流程。正式程序包、可见窗口视觉、原生游玩和设备验收仍待完成。

首轮 TLS 验证脚本的局部变量遮蔽了 `http` 模块，实际退出 `1`。首次 Tk 脚本在同一进程创建两个根窗口，测试采样回调在根窗口销毁后仍待执行，并出现 `Tcl_AsyncDelete`。保留两轮失败。更名 TLS 测试变量、停止采样并为每个 Tk 场景使用独立进程后，最终均通过。两次调整都在验证脚本中完成。

## 2026-11-19 手动备份与停止

在独立 Windows Tk 窗口用受控的慢备份复现。原来单击备份会在窗口线程里执行存档复制。测试将复制暂停约 0.7 秒，窗口的定时回调在此期间没有执行。按钮回调耗时 0.734 秒。

手动备份现在由后台线程执行。进行中窗口显示状态，备份按钮暂时禁用，停止按钮仍可用。备份成功及失败写入窗口状态行。停止后先等待已开始的备份结束，再释放数据库和存档锁。

- 三个独立 Windows Tk 进程验证了成功保存、备份中点击停止以及写入失败后重试。暂停复制期间，窗口能处理事件并拒绝重复备份。停止场景核对到存档锁仍由运行中的进程持有，备份完成后两端口和锁都可重用。
- 停止场景的存档在新进程重开。两个监听器均就绪，健康检查返回 200，备份文件与索引的 SHA-256 一致。
- 27 个相关检查通过。首轮单测夹具缺少运行时的设置字段，修正后该用例通过。Ruff 和差异检查通过。

运行的是源码窗口和 D 盘合成存档。证据在 `.cache/launcher-backup-ui-20261119`，含前后实测脚本、四个运行回执、首次测试 XML 及修正用例的 XML。
