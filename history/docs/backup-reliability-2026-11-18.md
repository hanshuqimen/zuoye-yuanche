# 自动备份与恢复验收

在独立 D 盘数据目录复现了两种故障。半写的 JSON 索引让自动备份中止，周备份也没创建。只留下当天索引时，任务误认已有日备份，返回成功却没有当天的数据库副本。证据保存在 `.cache/backup-reliability-20261118/reproduction.json`。

自动备份按主机 UTC 日期和 ISO 周检查数据库及其索引。文件缺失、索引无效、大小不符或 SHA-256 不符时，任务会为当前周期补建。轮换优先保留覆盖不同日期或周的有效备份，上限为 7 份日备份和 4 份周备份。自动轮换保留损坏文件、没有索引的数据库、手动备份和恢复前快照。索引用临时文件写完并同步后发布，SQLite 用同盘临时库生成副本。

管理 API 只列出通过文件检查和 SHA-256 校验的备份。恢复先锁定所选文件并复制到同盘临时目录，之后校验那份实际用于恢复的副本。即使原文件随后被正常轮换，候选仍能完成迁移与验收。激活保留已有的恢复前快照和回滚机制，因此现有存档存在无效实体引用时，管理员仍可保存现场并恢复一份有效副本。

## 命令行恢复与正在运行的服务

修复前的双进程复现中，服务侧在恢复前快照写完后提交新状态。命令行恢复成功退出，却同时覆盖了这次写入，恢复前快照也未记录它。复现使用 D 盘隔离数据库，保存在 `cross-process-before/verification.json`。

服务启动和命令行恢复现在持有同一数据目录的 SQLite 文件锁。锁覆盖服务启动、运行及后台任务退出，也覆盖命令行验证和恢复操作。活动服务持锁时，独立命令行恢复在打开业务数据库前退出 2。需要在线恢复时，使用该服务自身的管理 API。命令行的只读备份仍可在线运行。锁由实际连接持有，磁盘上的 `.save-owner.sqlite3` 文件存在时也能在连接关闭后重新获取。

## 2026-11-19 从损坏的存档目录恢复

原命令行恢复会先加载现用数据库。在 D 盘合成数据上，现用文件头损坏后，原命令以退出码 1 提前结束，同目录的备份仍通过 SQLite 完整性检查。

直接恢复遇到 SQLite 损坏时，命令提示使用 `--output` 将备份恢复到独立文件。新入口从所选数据目录的 `backups` 中读取原备份和索引，检查指纹及配置兼容性。随后在目标盘验证完整性、实体引用与结构并迁移旧版本，最后发布一个完整的 SQLite 文件。成功响应给出目标路径、字节数、数据库版本和 SHA-256。

```powershell
terralocal --data-dir "D:\旧存档" restore "manual-20261119T041013.102190Z.sqlite3" --output "D:\恢复目录\terralocal.sqlite3"
```

该命令交付数据库文件。恢复目录要供服务使用时还需要对应版本的配置和静态数据。本次验证使用源码命令及合成数据。

## 2026-11-19 数据和规则切换后的自动备份

## 2026-11-19 命令行原位恢复的存档保全
