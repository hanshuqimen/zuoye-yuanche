# 打包与备份恢复安全修复（2026-10-11）

本阶段修复全仓审计的 A01 和 A07。构建不再覆盖现有安装目录；备份先在临时库升级和验证，激活失败后自动恢复原存档。其他八项审计问题及完整玩法仍待处理，本阶段不代表成熟私服交付。

## 构建方式

`tools/build.ps1` 调用 `tools/build_release.py`。每次构建使用新的 `dist/releases/<UTC 时间与随机标识>/TerraLocal`，工作文件放在对应 `build/releases`；不删除、移动或覆盖旧 `dist/TerraLocal`、旧发行物、其 `data` 或链接目标。

`-Clean` 只传给打包器清理其缓存。输出目录必须留在项目内；拒绝经目录链接指向外部的输出根。新发行物不得混入 `data`、官方资源或指向其他目录的链接。只有打包成功、EXE `--version` 通过后才写入文件指纹清单。

```powershell
.\tools\build.ps1 -Clean
```

脚本最后输出新 EXE 路径。新发行目录不会自动接管原存档；现有客户端连接配置、资源和原正式 EXE 保留。后续部署及升级仍须使用已验收的兼容配置，并独立保存存档。

## 恢复方式

恢复仍检查备份哈希、数据库版本、GameData、掉落与寻访资料身份，随后：

1. 复制来源到活动数据库旁的独立临时目录。
2. 只在候选库运行迁移，核对当前版本、所需表/字段、SQLite 完整性和实体引用。
3. 取得维护锁，保存最新 `before-restore` 快照，再激活已验证候选。
4. 使用 SQLite backup 的事务提交写入现有数据库文件，保留文件路径，避免在 WAL 读者下直接换文件。
5. 激活或初始化失败时自动把最新快照还原，重新打开原库并返回原始错误；原数据可继续读取和写入。自动还原也失败时，明确报告保留的恢复前备份名称。

备份元数据也改为临时文件写完后替换。URI 只读连接正确处理包含空格、`#` 和 `%` 的存档路径。临时恢复目录使用配置数据盘，不使用 C 盘临时目录。
