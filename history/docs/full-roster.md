# 全角色与最高技能培养

`Sandbox` 账号预设及管理面板“干员 → 应用全角色、满潜满信赖和全技能专三”使用同一个领域操作。对当前选中的本地账号，授予匹配 GameData 中所有 `char_` 且 `isNotObtainable` 为假值的干员。未开放角色、敌方单位、召唤物与陷阱不作为可获得干员授予。

管理接口：`POST /api/gm`，请求体 `{"accountId":1,"action":"complete-roster"}`，需要管理会话 Cookie 与 `X-CSRF-Token`。返回 `roster` 包括总干员数、新授予数、实际修改数、专三技能数、无专精树技能数及信赖上限。GM 操作与结果写入审计日志。

| 项目 | 设置依据 |
| --- | --- |
| 潜能 | `character_table[charId].maxPotentialLevel`，协议 `potentialRank` 从 0 开始；定义 5 表示六潜，定义 0 的角色保持 0。 |
| 信赖 | `favor_table.maxFavor` 的原始信赖点数，不能把百分比 200 当原始点数写入。 |
| 通用技能等级 | `allSkillLvlup` 的条目数 + 1。低星与无主动技能角色遵循各自上限。 |
| 每个技能专精 | 该技能 `levelUpCostCond` 的前三级；完整三段树设为 3，无专精树设为 0。技能不存在时不创建虚构的技能。 |
| 精英阶段与等级 | 遍历全部通用升级、技能解锁与前三段专精的 `unlockCond`，取满足这些条件的最低阶段及该阶段最低等级。已有更高阶段或等级保留；跨精英阶段时经验清零。 |
| 训练计时 | 专精已完成后清除该技能未完成的训练时间，输出完成状态。 |

用户未要求等级拉满，因此此操作只补足技能专精所需条件。当前本地 V077 / 77.6.0 角色数据中，专精条件都是精二 1 级；实现仍逐条读取条件，不硬编码精二 1 级。若其他版本某技能要求精二 40 级，算法会提升至 40 级。

重复执行更新已有干员实例，不调用重复干员奖励逻辑，也不发放额外信物。不改变已有编队的干员实例 ID。领域操作全部在调用者事务中完成，中途出错时回滚；管理接口使用现有维护锁与 SQLite 写事务，仅影响目标账号。
